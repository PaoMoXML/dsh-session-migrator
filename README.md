# dsh-session-migrator

把旧会话、甚至整个工作区**迁移出 DSH**，并在需要时**连同工作区一起恢复**。

## 功能

- 设置 → **会话迁移**。
- 迁移条件：将 **X 个月以前**的会话迁出；时间范围可填 **0–120**，**默认 1（1 个月以前）**，`0` 表示不限时间（包含本月）；另有 1 / 3 / 6 个月和「全部（含本月）」快捷范围；扫描结果默认不勾选。
- 默认**不迁移**带「备注」或「待办」标记的会话；必须先勾选「允许选择带备注或待办标记的会话」，再手动勾选具体会话。
- 待迁移列表和已迁移列表在设置页内用 **Tab 切换**；扫描结果和归档列表都**按工作区分类，再按最后活动月份分组**；工作区顺序跟随 DSH 当前 `workspaceIds`，工作区重排会同步；已删除的工作区保留原归档分组并排在最后；每个月可全选。进入任一 Tab 时**工作区和月份都默认收起**，不会自动展开任何数据。
- 已迁移条目会保存迁移时的 `workspaceId / workspaceTitle / workspacePath`，工作区删除后归档列表仍显示「原工作区名（已删除）」分组。
- 列表中显示会话的 **Git 分支**（来自 `dsh-session-branch` 的记录；分离 HEAD 显示短 commit）、父会话信息和 DSH 归档状态。
- 扫描结果包含**运行中的会话**（显示「运行中」标记、不可勾选），避免当前范围内已打开的会话被静默隐藏；默认 1 个月仍按时间过滤，要看本月请把范围设为 `0` 或点「全部（含本月）」。真正迁移时仍会跳过运行中的会话。
- 迁移父会话时会**级联迁移它的全部子代理会话**（`origin: subagent` 的整棵 descendant 树），恢复父会话时也会把这些子代理目录一起恢复；挂在父会话下的子代理不单独出现在归档列表中，只在父会话行显示“+N 个子代理”。
- 父会话已不在 `sessions` 目录的**孤儿子代理**会作为「子代理残留」出现在待迁移列表（当前月份也能看到），并按它父归档条目所属的工作区分组；可单独勾选迁移，加到已有父归档条目下后，会和父会话一起恢复。孤儿子代理的日期与月份按会话头 `createdAt` 计算，不采用文件修改时间，避免会话格式升级重写文件后把旧子代理误显示成本月新会话。
- 迁移目录默认是 `$DSH_HOME/session-migrator/archive`，页面「迁移目录」可填写其他绝对目录；执行迁移时保存该设置，之后仍可在归档列表恢复。
- 迁移/恢复超过 200 个会话时客户端自动分批请求；一次迁移的多个批次会合并到同一个「一键恢复本次迁移」范围。
- 迁移后提供「一键恢复本次迁移」；归档列表支持多选恢复与全部恢复。
- 已迁移列表支持按标题、路径、工作区、备注或会话 ID 搜索；搜索只过滤展示，不改动归档数据。

### 整区迁移工作区

待迁移 Tab 下方的 **「整区迁移工作区」面板**（默认收起）按 DSH 的工作区顺序列出全部当前工作区，每个工作区显示路径、会话数、其中已在归档目录的数量，以及「迁移整个工作区」按钮：

- **忽略时间范围**：该工作区的全部会话（含本月、含空白新会话）一起迁出；会话自身的备注/待办保护仍然生效。
- **完整成员口径**：DSH 内存里的 `workspace.sessionIds` 会过滤掉已迁走或不在磁盘的成员，所以插件同时**只读** `<DSH_HOME>/storages/workspace.json` 取持久成员，再并上本插件已归档到该工作区的会话。因此「已在归档目录」的数量、缺失文件预检和恢复配方都以完整成员为准。
- **整区预检**：只要有一个会话正在运行、带备注/待办（含其子代理）且未允许、或文件缺失且没有归档条目，整个工作区拒绝迁移，**不会先移走一部分**。工作区登记里直接包含的子代理会话会按父会话的级联处理，不会误报“文件缺失”。
- 全部会话迁移成功后，才通过 `ctx.workspaceRegistry` **删除工作区登记**；部分会话失败则保留登记（已成功的会话留在归档里，重试时不会重复移动）。
- **失败与并发收口**：迁移期间工作区成员发生变化（例如另一标签页新建/attach 了会话）、或登记删除失败时，插件会**回滚本次已移走的会话**并继续保留工作区登记；若个别会话回滚失败，则保留恢复配方，等会话恢复时再挂回。删除登记的调用即使报错，也会先确认登记是否真的消失，避免误回滚。
- **项目目录不会移动**：只迁移 DSH 的工作区登记和会话文件，磁盘上的代码目录原地保留。

### 恢复工作区

- 已迁移 Tab 顶部新增 **「已迁移工作区」** 列表：显示工作区标题、路径、待恢复会话数、迁移时间，可单个「恢复工作区」。
- 恢复工作区会：先恢复它仍留在归档目录的会话 → 按**原目录、原标题**重建工作区登记（若同路径工作区已存在则复用）→ 按原顺序把会话挂回工作区 → 按迁移时的相邻工作区把登记插回原来的顺序位置。
- **可重试**：原项目目录缺失时，会话照样恢复，工作区重建失败并保留配方；目录回来后再点「恢复工作区」，插件只处理仍在归档的会话、已在磁盘的会话只重新 attach，不会把已恢复的会话误报成 “not in archive”。归档文件已损坏/丢失（列表显示「归档文件缺失」）的成员不会计入待恢复配方，工作区条目仍可收尾。
- 恢复**普通会话**时，如果该会话属于某个已迁移工作区，会**自动顺带重建该工作区**并把当时在场的会话挂回去；提示里会显示「并重建了 N 个工作区」。
- 「一键恢复本次迁移」、多选恢复、全部恢复都走同一套联动逻辑。
- 工作区归档条目在**它的会话全部恢复后**才删除；部分恢复时保留条目，后续恢复继续挂回同一个工作区。
- 重建出来的工作区登记会得到**新的 workspace id**（DSH 不提供指定 id 的创建接口），但路径、标题、排序与会话归属都会还原；归档条目保留原 id 与路径，列表按路径自动对上新的登记。

- 归档列表显示每个会话的：
  - 标题、原工作目录、最后活动日期、大小；
  - 备注/待办的内容、类型与完成状态；
  - 是否在 DSH 中**已归档**（恢复后保持原状态）。
- 恢复后会话回到原来的项目目录与会话目录，DSH 会话列表可正常打开；已归档的会话仍在 `archivedSessionIds` 中，因此继续处于归档状态。

## 工作原理

DSH 的 JSONL 持久化后端把每个会话存成 `$DSH_HOME/sessions/<项目目录>/<会话目录>/session.vN.jsonl.zstd`。本插件把**整个会话目录**移动到插件归档目录，因此 `sessionPersistence.list()` 不再列出它，DSH 会话列表随之消失；恢复时再整体移回原路径。文件只移动，不删除、不重写。

工作区是 `$DSH_HOME/storages/workspace.json` 里的登记（目录 + 标题 + 会话归属 + 顺序）。运行中的 DSH 在内存里缓存这份登记，**直接改文件会被下一次写入覆盖**，所以本插件只通过 `ctx.workspaceRegistry` 的 `delete / create / insertBefore` 与实体方法 `setTitle / attachSession / insertSessionBefore` 操作登记；`workspace.json` 只在整区迁移统计/预检时**只读**打开（读失败时退回 registry 投影，不影响会话迁移）。

数据目录：

```text
$DSH_HOME/session-migrator/
  entries/<session-id>.json   # 每个已迁移会话的索引、原路径、实际归档路径与展示元数据
  workspaces/<workspace-id>.json  # 每个已迁移工作区的恢复配方：路径、标题、会话顺序、原顺序
  archive/<session-id>/       # 默认归档根下的原会话目录
  state.json                  # archiveRoot（用户手选的迁移目录）与上次迁移批次
```

迁移目录可在页面手动指定；每个 entry 保存实际 `archiveDir`，所以修改默认目录不会影响旧归档的恢复。归档根不能位于 `$DSH_HOME/sessions` 内。工作区条目很小，固定放在插件根目录，与用户选择的会话归档根无关。

归档状态来自 `workspaceRegistry.archivedSessionIds`，本插件不修改归档集合，所以：

- 迁移一个已归档会话 → 恢复后仍然是归档状态；
- 迁移一个正常会话 → 恢复后正常显示；
- 整区迁移时，工作区里已归档的会话一起迁出，恢复工作区后它们仍保持归档状态。

工作区被**手动**删除（不是本插件迁移）后：DSH 的 workspace 记录连同 `sessionIds` 归属一起删除，恢复的会话仍能打开（`cwd` 保留），但会作为「未分组」会话出现；如果该会话原本已归档，恢复后仍在归档集合中。之后重新创建同路径工作区也不会自动把旧会话重新挂回去——这种场景需要先做整区迁移，才能连带恢复。

## HTTP 路由

客户端只通过以下 loopback 路由访问宿主（全部 `POST`，要求请求头 `x-dsh-session-migrator`）：

| 路由 | 用途 |
|---|---|
| `/session-migrator/scan` | `{ months }` → 可迁移会话、统计与按工作区的整区迁移概览 |
| `/session-migrator/migrate` | `{ months, sessionIds, allowMarked }` → 迁移所选会话 |
| `/session-migrator/archive` | `{}` → 归档会话、已迁移工作区与上次迁移批次 |
| `/session-migrator/restore` | `{ sessionIds }` → 恢复所选会话（并联动恢复所属工作区） |
| `/session-migrator/workspace-migrate` | `{ workspaceId, allowMarked? }` → 整区迁移一个工作区 |
| `/session-migrator/workspace-restore` | `{ workspaceIds }` → 恢复整个工作区及其会话 |

路由限定 loopback（或已配对的 remote-web-ui 设备），拒绝跨站表单；响应带 `cache-control: no-store`。

## 已知边界

- 只支持提供 `location.path` 的按会话文件后端（当前产品自带的 JSONL 后端）；其他后端会在扫描时跳过并计入统计。
- 正在运行的会话会显示但不可勾选；挂在父会话下的子代理会随父会话级联迁移；孤儿子代理会显示为「子代理残留」；空白新会话与没有 `cwd` 的会话不会进入普通扫描列表，但**整区迁移**会带走空白会话。
- 整区迁移要求该工作区里没有运行中的会话、没有未允许的备注/待办会话（含子代理）、没有既不在磁盘也没有归档条目的会话，否则整个工作区不动。成员口径优先读 `<DSH_HOME>/storages/workspace.json`；该文件不可读时退回 registry 投影，统计可能少算被过滤掉的旧成员，但不会删除或破坏数据。
- 恢复工作区要求原项目目录仍然存在且是目录（本插件不创建用户目录）。目录缺失时会话仍可恢复，但工作区重建失败并显示失败原因；条目保留，目录恢复后可再次点「恢复工作区」，已恢复的会话只重新 attach。
- 工作区恢复后 workspace id 会变化；归档条目里的旧 id 不再对应任何登记，列表按 `workspacePath` 对上新登记。DSH 的工作区名唯一性检查只在重命名命令里做，本插件按原标题 `setTitle`，若同名工作区已存在会出现重名，属预期还原行为。
- 同一个 `$DSH_HOME` 被 desktop/web 两个 profile 共用时，另一个进程正在写的会话可能在移动时报文件占用；该会话会出现在失败列表里，不影响其他会话。
- 迁移后 DSH 会话列表的刷新依赖客户端的 `sessions.refresh()`；如果当前版本没有该方法，重新加载页面即可看到最新列表。工作区列表由 `useWorkspaces` 的增量推送自动更新。
- 归档目录中的会话仍占用磁盘；本插件不删除会话数据。
- Host 侧 `index.js` / `lib/*.js` 的改动需要重启 DSH 进程才会加载新模块；`client.js` 刷新页面即可。
