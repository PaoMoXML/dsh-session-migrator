# Agent Note: 工作区整区迁移与恢复

Status: implemented

## Problem

插件原先只按「月份」迁移单个会话：会话目录被移走后，工作区登记仍然留在 DSH 侧栏里，成为一个空壳或半空壳；恢复会话时 `workspaceRegistry` 不包含这些会话，于是它们落到「未分组」。用户希望一次迁走整个工作区，并在恢复时连带把工作区登记和会话归属一起还原。

## Decision

工作区作为一等迁移对象，与会话文件分离处理：

- **整区迁移**由待迁移 Tab 的「整区迁移工作区」面板发起，忽略时间范围，一次性迁走该工作区登记里已归属的全部会话（含本月与空白会话）。带备注/待办、正在运行、文件缺失这三类会话会触发**整区预检拒绝**，一个文件都不移动；全部会话迁移成功后才删除工作区登记，任一失败则保留登记。
- 已经由本插件迁移过的会话不再重复移动，但会并入工作区恢复配方（`sessionIds`/`pending`），所以「先零散迁过几个会话，再整区迁走」不会卡在“文件缺失”。
- 工作区恢复条目写入 `$DSH_HOME/session-migrator/workspaces/<id>.json`：原 workspace id、路径、标题、有序列的 `sessionIds`、仍待恢复的 `pending`、迁移时的完整 `workspaceIds` 顺序。条目在 `pending` 清空前一直保留。
- **迁移后置校验与回滚**：会话目录移动完成后再核对一次完整成员（并读取最新的持久登记），删除登记前再核对一次；成员变化、登记消失、删除失败都按逆序把本次移走的会话（含子代理）移回原目录，再撤掉恢复配方。只有回滚本身也失败时才保留配方（此时它可能对应一个仍在册的工作区，归档 UI 不展示，但恢复会话时仍可用它挂回）。
- **完整成员口径**：`workspace.sessionIds` 是经过 header 索引过滤的投影，重启后看不到已迁走的成员。统计、预检、配方与会话成员比较都以「registry 投影 + 只读 `storages/workspace.json` 持久记录 + 本插件归档条目」的并集为准；持久文件不可读时退回投影。坏掉（`missing:true`）的归档条目不并入 `pending`，否则配方永远无法收尾。
- **子代理成员**：登记里直接包含的子代理会话，只要它的某个祖先仍是本工作区的可迁移成员，就交给祖先的级联迁移，不再当作“文件缺失”拒绝；没有祖先成员的子代理会给出专门错误。整区统计里的 `marked` 也计入这些子代理的备注/待办，保证“允许备注/待办”开关可见。
- **重试幂等**：项目目录缺失导致登记重建失败时，配方按「仍在归档或仍在磁盘」重算；目录回来后重试只 move 仍归档的会话，已在磁盘的会话只重新 attach，不重复计入失败。
- **恢复**只走 `ctx.workspaceRegistry` 公共 API，绝不直接改 `workspace.json`：`resolveByPath` 复用同路径登记，否则 `create` 后 `setTitle`；用完整顺序快照找「迁移时排在它后面的第一个仍在册工作区」作为 `insertBefore` 锚点；会话按 `attachSession` 反序挂入（或复用登记时用 `insertSessionBefore` 校正顺序）。
- 恢复普通会话时，如果命中了工作区条目的 `pending`，自动重建该工作区并挂回当时在场的所有会话；显式「恢复工作区」则先恢复剩余会话再重建登记。workspace id 会变化（DSH 没有指定 id 的创建接口），归档条目保留旧 id 与路径，分组按路径自动对齐。
- **不移动项目目录**：工作区迁移只动 DSH 登记和会话文件。

## Alternatives considered

- **直接改写 `storages/workspace.json` 保留原 workspace id**：能让 id 完全不变，但运行中的 `WorkspaceRegistry` 在内存里缓存 `global` 与实体快照，下一次任何登记写入都会覆盖外部修改，还可能触发 `validateStoredState` 的 path/session 双占用不一致。放弃。
- **整区迁移逐会话尽力而为，能迁多少迁多少，然后删登记**：实现更简单，但会留下一个缺会话的工作区或一个“半空壳”，恢复时无法判断哪些会话本该回来。改为预检失败即整体拒绝。
- **把项目目录一起搬进归档目录**：对超大仓库/含 `.git` 的目录代价高，且恢复失败会波及真实代码目录。用户明确选择只迁移登记与会话，目录原地保留。
- **恢复时覆盖已有同路径工作区**：已存在的登记可能有用户新建的会话；复用登记并只挂回归档会话，比删除重建更安全。
- **把工作区条目放进用户可选的 archiveRoot**：条目只是小 JSON，跟会话归档根绑定会让“换迁移目录”影响恢复配方；固定在插件根目录。

## Consequences

- 恢复后的 workspace id 与原 id 不同；依赖旧 id 的外部记录（如其他插件的按 id 引用）不会自动迁移。归档列表与分组用路径兜底。
- 工作区登记删除是不可回滚的破坏性步骤，因此恢复配方先落盘、删除失败回滚条目；`archive()` 还会清掉“登记仍在”的残留条目（说明删除步骤失败）。
- 预检拒绝让用户必须先处理运行中/备注待办/缺失文件，整区操作才能进行；这是有意用可理解性换“绝不半途停下”。
- 恢复依赖原项目目录存在；目录缺失时会话照样恢复，但工作区重建失败并保留条目，等目录回来后可以重试；重试不会把已恢复会话误报为失败。
- 回滚失败时保留的配方可能对应一个仍注册的工作区（归档 UI 隐藏它）；这是为了让“文件已移走但登记还在”的异常状态仍有一条恢复路径，代价是这种状态的条目不能从 UI 直接手动清除。
- 整区统计依赖只读 `workspace.json`；文件不可读或格式变化时退回 registry 投影，统计口径变窄（可能少算被过滤的旧成员），但迁移/恢复仍按可用成员执行，不会写坏登记文件。
- 新增两个 loopback 路由（`workspace-migrate` / `workspace-restore`）与一类归档条目；旧版本插件留下的条目仍能读（`pending` 缺省等于 `sessionIds`）。
- 测试从 14 项扩到 27 项，覆盖整区迁移、显式/联动恢复、受保护会话拒绝、已零散迁移会话、空工作区、子代理成员级联、子代理备注统计、删登记失败回滚、迁移中成员变化回滚、坏归档条目不进配方、目录缺失后重试、持久登记补充被过滤成员；Host 侧 27 项全绿，`node --check` 全部通过。
